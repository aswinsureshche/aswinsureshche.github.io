Why add a network sensor

Wazuh catches brute force, lateral movement and process attacks once they touch a monitored host. But a plain Nmap SYN scan writes nothing to the Windows event log, so a host-only setup never sees the recon. Suricata on a span port closes that gap.

The kill-chain rule

Rule 100040 only fires when one IP completes the chain: a brute force that succeeds, then exploitation-stage activity within 15 minutes.

<!-- local_rules.xml -->
<rule id="100040" level="15" timeframe="900">
  <if_matched_sid>100021</if_matched_sid>
  <if_sid>100030,100031,100032</if_sid>
  <same_source_ip />
  <description>Multi-stage attack
    from $(srcip)</description>
  <mitre><id>T1110</id><id>T1003</id></mitre>
</rule>
  • Chained, not counted. Single alerts are noisy; requiring the sequence cuts false positives.
  • Same source. same_source_ip keeps two unrelated events from combining.
  • Bounded window. A 900-second window keeps the chain tied to one intrusion.

Safety rails

  • Attack scripts refuse any target outside private (RFC 1918) address space and ask for confirmation before firing.
  • Metasploit runs only scanner modules and lab-only exploits against Metasploitable, never production software.
  • The Python tooling is read-only against the Wazuh API.
